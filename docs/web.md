# ブラウザ版(WebGL / WebXR)

設計書をもとに、Three.js + WebXR で作ったブラウザ版。ビルド不要の静的サイトで、vrgame2 のゲーム選択画面から起動できる。

- 公開先:https://shuji30.github.io/vrgame2/games/tread-revolt/ (選択画面 https://shuji30.github.io/vrgame2/ の4番目)
- 対象:PC の Chrome / Edge(デスクトップ)、PCVR(OpenXR。Pimax 8KX で確認する前提)
- ハンコン:vrgame2 の ffb-bridge を起動しておく。設定画面の「ハンコン」から ZIP(vrgame4 と同じ `vrgame2/downloads/ffb-bridge.zip`)をダウンロードできる。`https://shuji30.github.io` と `http://localhost:8090` はブリッジの既定の許可リストに入っている

## 入っているもの

| --- | --- |

## 手元で動かす

```bash
npm start      # http://localhost:8090/
npm test       # 中核ロジックのテスト(node --test)
```

確認用の URL パラメーター:`?stage=0`(0〜10 のステージから開始)、`&vehicle=mech`、`&view=diorama`、`?training`、`?versus=dom`、`?unlock`(全ステージを選べる)、`?bot`(自機を AI に操縦させる)、`?nolock`(ポインターロックしない)。

開発用の道具:

- `node scripts/snap.mjs "<url>" out.png [秒] [JS]` … ヘッドレス Chrome で開いて、コンソールのエラーとスクリーンショットを取る
- `node scripts/nettest.mjs` … 2つのタブを「同じPCで試す」でつなぎ、オンラインの同期を確かめる

## BGM

BGM は `web/assets/bgm/<曲>.m4a`(AAC-LC、48 kHz・ステレオ)を再生する。読み込むまでは `web/src/music.js` の合成で鳴らす。曲の id は title / training / area1〜4 / boss / versus。

- `<曲>.m4a` が無ければ `<曲>.wav` を探す。`node scripts/render-bgm.mjs`(`npm start` を動かしておく)で合成の曲を WAV に書き出せる(今は使っていない)
- 対戦のアリーナは `arena1〜4`(ARENA_LIST の順)を探し、無ければ `versus` を流す
- 再生時に 2.4 倍する(WAV を音割れしないよう下げて書き出していた名残)
- `*.m4a` と `*.wav` は Git LFS の対象(`.gitattributes`)

## スマホ・タブレット(タッチ操作)

タッチの端末(`pointer: coarse`)では、プレイ中だけ画面にゲージとボタンを重ねる(`web/src/input/touch.js`)。値は `InputManager.poll` で共通アクションにまとめる。

- 画面の左右の端に履帯のゲージがある。ゲージを直接触った高さがそのまま出力(中央 0、上 = 前進、下 = 後退)。指を離すと 0 に戻る。スティックの表示はない
- 砲塔は画面の中ほどを左右になぞる
- 簡易操作モードでは左ゲージ = 前後、右下の横向きゲージ = 旋回
- ボタン:主砲、副武装、曲射(押している間)、ギア(1→2→3→R)、視点、ポーズ
- 指が離れた知らせ(pointerup)が届かなくても効かなくならないよう、pointercancel・lostpointercapture・ポーズ(非表示)・アプリの切り替え(blur / visibilitychange)で必ず指を離した状態に戻す。同じゲージやボタン・なぞりの場所に新しい指が触れたら、前の指は捨てて新しい指を追う(知らせが途切れた指が残ると、砲塔が回り続けて車体が横へ流れて見えたり、ボタンが効かなくなる)。画面から指がすべて離れたら(touchend で 0 本)すべてを戻す
- なぞりは触った位置からのずれで砲塔を回す速さが決まる。指を置いただけのずれで回らないよう、12px までは回さない
- 主砲・煙幕・視点などの押した瞬間の操作は、物理(60Hz)を 1 歩も進めないフレームで捨てずに次へ持ち越す(90Hz・120Hz の画面のスマホで、タップが効かないことがあった)
- ゲームパッドは、軸は一度中央に戻るのを見てから、ボタンは一度離れるのを見てから使う。止まっているときに軸が中央にない機器(スマホが内蔵の機器をゲームパッドとして見せることがある)を倒しっぱなしと取り違えると、両方の履帯が前進いっぱい・砲塔が回り続けたまま(視点が回るので横へ流れて見える)になり、入力は大きいほうを採るのでゲージの下方向が効かなくなっていた(v0.2.17 で直した)
- ポーズ画面の下に、ポーズした瞬間の入力の状態(使っている入力、ゲームパッドの軸とボタン、タッチの値、押しているキー)を出す。勝手に動くときの原因を確かめるため
- 始めるときに全画面・横向きにする(できない端末では何もしない)。タッチの端末は影を既定で切り、解像度を 1.5 倍までにして軽くする
- 確かめ方:Chrome の開発者ツールでスマホの表示(横向き)にして `?training` を開く

## 効果音

- 履帯の板の金属音(ガラガラ)は控えめにしてこもらせ、速くなるほど転がる音に溶け込ませる。自車は車内なのでさらにこもらせる。設定の「履帯の音」(既定 0.5)で音量を変えられる(v0.2.20)

効果音は `web/src/audio.js` で合成している。`web/assets/sfx/<名前>.wav`(無ければ `.m4a`)があれば、合成の代わりにそのファイルを鳴らす。差し替えるときは、同じ名前のファイルを上書きする。消すと合成に戻る。

- `node scripts/render-sfx.mjs [名前 ...]`(`npm start` を動かしておく)で、今の合成を書き出す(44.1 kHz・32 bit float・モノラル)。すでにあるファイルは上書きしない。上書きは `--force`
- 一発ものの名前は `audio.js` の `SFX` のキー(cannon、explosion、missile など)。強さ(主砲の溜めなど)は音量で、pitch は再生速度で表す
- ループの素材:`loop-clank`(履帯の板の音。1 秒に 48 枚の速さで作る)、`loop-engine`(ディーゼル。1 秒に 30 回の爆発)、`loop-missile`(ミサイルの噴射)。速さに合わせて再生速度を変えて鳴らすので、この基準の速さに合わせて作る
- 転輪のゴロゴロ、砂利、超信地の軋み、メカのサーボ、無線のピッは合成のまま(ファイルにはしていない)
- 音はモノラルで作る(位置に合わせて左右に振るため)
- どれから置き換えるとよいかと、AI で作るときのプロンプトは `docs/sfx-prompts.md`

## 公開(vrgame4 の SKY RUNNER と同じ流れ)

1. `web/src/version.js` の `VERSION` を上げる
2. vrgame2 を `git pull` してから `node scripts/publish.mjs`(vrgame2 の `games/tread-revolt/` へコピー。プログラムは毎回ちがう名前の `js-*/` に置き、GitHub Pages のキャッシュで新旧が混ざらないようにする)
3. vrgame2 で `npm test` → commit → push

`js-*/` は直前の 2 つまで残す(新しさはフォルダ名の末尾の時刻で決める)。Git LFS の実体を取っていないクローン(クラウドの作業環境など)では音のファイルがポインタになっているので、それは写さず公開先のものを残す。
4. `https://shuji30.github.io/vrgame2/games/tread-revolt/version.json` で反映を確かめる

ページは開いたとき・タブに戻ったとき・メニューへ戻ったときに `version.json` を読み、公開されている版がプログラムの版と違えば `?v=<版>` を付けて一度だけ読み込み直す(遊んでいる最中はしない)。ブラウザが古い index.html を使い続けて、直した不具合が残って見えることがあったため(v0.2.18 から)。

## オンライン

ホスト・クライアント方式。ホストが敵・命中・撃破・ミッションの判定を持ち、15Hz で状態を配る。自分の車両は各自が動かして送り、弾の発射はイベントで送る。

- つなぎ方:WebRTC のデータチャネル。接続の仲介だけ PeerJS の公開サーバー(0.peerjs.com)を使う
- 中継(TURN):Metered の Open Relay(日本の中継サーバー)を使う(v0.2.26 から。`web/src/net/ice.js` の `TURN_SERVERS`、手順は `docs/turn.md`)。オンラインの画面の「中継(TURN)を試す」で確かめられる。Cloudflare Realtime の TURN にも切り替えられる(`cloudflare/turn-worker/`)。`TURN_URL` が空のときや合言葉を取れないときは PeerJS の既定(Google の STUN と、PeerJS 運営の無保証の TURN)。URL に `?turn=<Worker の URL>` を付けるとその場で試せる
- 「同じPCで試す」をオンにすると、同じブラウザのタブ同士で BroadcastChannel でつながる(1台で確かめる用)
- vrgame4 のランキングに使っていた Supabase のプロジェクトはなくなっていた(2026-11-14 に確認)ので使っていない

## 主砲と曲射(v0.2.31)

- 戦車の主砲は砲身 2 本。左右交互に撃ち、撃った分を 1 発ずつ装填する(1 発ぶんは reload×0.7。2 発で reload×1.4)。装填のゲージは 2 発ぶんで、真ん中に目盛りがあり、半分を超えると 1 発撃てる(黄緑)。満タンで 2 発(緑)
- 曲射は 2 発ぶんを使う
- 曲射の向きの吸いつけ:曲射の目標(照準が合っている敵、または砲塔の向きから ±22° 以内の敵。発射台を優先)が砲塔の向きから 10° 以内なら、着弾の印と弾をその目標へ向ける
- VR の曲射は距離も自動(以前はスティックを外へ倒した量・レバーを開いた量で距離を合わせていて、2 面目の発射台に当てにくかった)。ハンコンはハンドブレーキを引いた量で距離を決め、近くの目標に吸いつく(以前どおり)

## 歩行メカの炸薬パンチ(v0.2.32)

- 主砲のボタンを押したとき、拳の届く所(自分と相手の半径の外側 2.6m 以内、正面 ±45°)に敵がいれば、主砲を撃たずに左腕で殴る。威力 75(軽戦車は 1 発)、次に殴れるまで 1 秒。どの入力(キーボード・パッド・VR・ハンコン・スマホ)でも同じ
- 当たり判定は、相手の胴の高さで水平に、ごく短い距離だけ飛ぶ見えない弾(kind: 'punch')で行う。命中・ボスの部位・装甲に弾かれる・オンラインでホストへ送る、を主砲の弾と同じ仕組みで扱う
- 見た目:左腕を前へ振り上げて拳を打ち出し、拳の先で炸薬が弾け、腕の後ろの排出口から空薬莢(真鍮色)が跳ね出して、回りながら落ち、地面で弾む(`Fx.casing`)。自機は FFB の反動と振動
- 特定作品の名称・デザインは使わない(CLAUDE.md)。仕組みだけを、このゲームの名前(炸薬パンチ)と見た目で作った
- 歩行メカはいちばん速い(最高速 14.5・加速 13・旋回 1.75。軽戦車は 13・11・1.55)

## 敵の動きと難易度

難易度は、敵の弾の威力・ばらつき・装填の速さに加えて、敵の戦車の動きの量(`DIFFICULTY.move`)を変える(v0.2.22)。

- イージー(0):射程内で見えたら止まって撃つ
- ノーマル(1):撃ったあとの装填中に、相手から見て横へ 9〜15m ずれ、遠ければ少し詰め、近すぎれば下がる(6 割の装填で)。撃つときは止まる
- ハード(2):ノーマルの動きを 9 割の装填で行い、ずれる向きは相手の正面から外れる側。接近のときは 2 両以上なら左右に分かれ、より後ろ寄りへ回り込む
- 攻撃中に動いている時間の割合(操縦役で 1-1・1-2・2-1 を測定):イージー 6%、ノーマル 38%、ハード 53%。クリアできる割合は変える前とほぼ同じだった
- 対戦のボットは別の動き(攻撃中にときどき動き回る)のまま

## バランスの確認(操縦役による測定)

`node scripts/balance.mjs [ステージ] [難易度] [車両]` で、テスト用の操縦役(`web/tests/pilot.js`)に各ステージを遊ばせる。
操縦役は「見えている敵を止まって撃つ、目標へ向かう、発射台は曲射、ボスは弱点へ回り込み、装填中は横へ動く」だけの単純なもので、人より下手。

2026-11-14 の結果(ノーマル・中戦車。v0.2.8):1-1、1-2、1-B、2-1、2-B、3-1、3-2、3-B、4-2 をクリア。3-B は乱数の種を変えた 4 回中 3 回、4-B(最後のボス)は 4 回中 2 回クリア。4-1 は操縦役が部屋の間を移動しきれず時間切れになるが、部屋ごとに置いて戦わせると 9 部屋の戦闘は合計約 120 秒(制限 480 秒)で終わり、門も順に開く。

`node scripts/balance.mjs <ステージ> normal medium 4` のように最後に回数を付けると、乱数の種を変えて遊ばせる。

この測定で見つけて直したもの:見通しの判定が薄い壁をすり抜けていた(敵が壁越しに見えていた)、区画制圧で撃破されるとスタート地点まで戻された(中間地点を追加)、掘削機は突進が壁に届かないと弱点が開かなかった(過熱で必ず止まるようにし、上の排気口を撃てるようにした)、浚渫要塞が吸気口を壊したあと二度と浮上しない、区画制圧のスタート地点が柱と重なっていた、自動仰角がボスの低い弱点を狙えず胴体に当たる、曲射の自動の距離が別の敵を選ぶ。

## ハンコンのハンドル

- 「ハンドルの回転角(ドライバー設定)」(`steer.wheelDeg`、既定 900°)はドライバーの設定と同じ値にする。「ハンドルの効く角度」(`steer.lockDeg`)の既定は 180°(左右に 90° ずつ)。保存済みの設定は書き換えない
- ハンドルは砲塔の旋回速度。効く角度で最大の速さになる
- ハンドルを中央(不感帯の内側)にして 1 秒たつと、砲塔が車体の正面へゆっくり戻る(旋回の 6 割の速さ。v0.2.30)。手を離すとセンタースプリングでハンドルが中央に戻るので、照準も正面に戻る。速度制御はそのままで、敵に照準が合っている間と撃ってから 2.5 秒は戻さない(狙いを保ったまま走れるように)。設定の「ハンドルを中央にすると砲塔が正面へ戻る」で切れる。共通アクションの `turretCenter`
- ソフトロック:効く角度を超えて回すと、FFB で中央へ押し返す(`mapSteer` の `beyond` → `readWheel` の `steerBeyond`・`steerSign` → `FfbModel`)。数度超えたところで強く効き、全体の強さ(ゲイン)を下げても弱まらない。向きは砲塔の旋回限界とそろえてあり、「FFB の左右を反転」も共通で効く。強さは設定の「ソフトロック」(0〜1、既定 0.8、0 で無効)
- ハンドルを物理的に止めたいときは、ドライバー側の回転角も効く角度と同じにし、「ハンドルの回転角」も合わせる
